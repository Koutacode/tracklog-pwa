# TrackLog v0.1.68 UI改善・更新案内

## 変更前後

| 変更前 | 変更後 |
| --- | --- |
| TrackLog運行アシスト | アプリ表示名をTrackLogに統一（Android、開始画面、PWA、通知） |
| 積込・荷卸・休憩・休息の開始ボタンが名詞のみ | 「開始」を明記。終了ボタンと区別しやすくした |
| その他作業・フェリーの終了操作が折り畳み内に隠れる | 進行中の状態を見出しに表示。初期表示・新規開始時に展開し、手動折り畳みも尊重 |
| 小画面のその他操作は4列・小さい文字 | 幅480px以下は2列・14pxに拡大 |
| 横向きODO画面で内容がパネル外へはみ出す | 入力欄の幅を制限し、画面内スクロール、戻る／確定を48px以上にした |
| 給油量が無効でも記録ボタンが有効で無反応 | 無効値では無効表示。入力ラベル、ダイアログ読み上げ情報、Escape／Tab移動を追加 |

## 維持した機能とデータ

運行開始・終了、積込・荷卸・休憩・休息・その他、フェリー、給油、高速開始・終了確認、AI要約・コピー、履歴・日報、ODO入力、位置記録・通知・管理者画面・同期・更新経路を維持する。変更は表示と入力画面が中心で、DBスキーマ、保存キー、運行保存処理、同期処理は変更しない。

Android packageは `com.tracklog.assist`、配布先と既存Actions署名を維持。公開前比較で旧署名APKに存在するSCHEDULE_EXACT_ALARMがローカル生成物では欠落すると分かったため、既存権限の宣言をmanifestに明記して保持する。新しい権限要求操作は追加しない。名称変更は別アプリ化ではない。実運行・本番Supabase・利用者端末のIndexedDB/localStorageへ接続・読取り・書換え・削除をしていない。端末内データを直接検証したという意味ではない。

## 検証記録

基準main: `36089e3274d693c91f9c1c41b59ac7af941eab54`（元リポジトリ配布を復元したPR #22）。開始時の公開版はv0.1.66/code64、v0.1.67タグは使用済み。未使用のv0.1.68/code66を採用（package/lock/Gradleは基準main時点で既に同値）。

変更前・変更後ともNode22、JDK21、Android SDK36/Build Tools36で型検査、既存ロジック試験、隔離PGlite同期24項目、CSP、Web build、オフライン38資産、Capacitor sync、Android単体85件・本体/debug androidTest APKコンパイルに成功。lint専用scriptは存在しない。既存のReact test renderer非推奨・Vite chunk警告は継続するが失敗はない。

追加した再現可能な回帰試験は `npm run test:logic` に含む。

- `StoppedView.test.jsx`: 開始/終了の呼出先、処理中の操作無効化、開始不可でも実行中操作は終了可、折り畳み状態、運行終了ODO確認経由。
- `InputDialogs.test.jsx`: 給油の空欄/ゼロ/不正数/小数、キャンセル・Escape、再表示の入力初期化、休息の0km入力、処理中の重複確定防止。
- `activeTripRestart.test.ts`: fake-indexeddb内の合成進行中運行・ルート・未同期イベントを作り、DB close/open前後の全テーブル一致、revision/mutation ID保持、二重開始/終了の拒否を確認。外部fetchを禁止してネットワーク0件。

Browser plugin not available のため、一時Playwright + Chromium、localhostの合成fixtureで実際のUIコンポーネントを検証した。外部通信を遮断し、320×640、360×780、412×915、780×360、900×800でページ識別、非空画面、フレームワークエラーなし、pageerrorなし、スクリーンショット、操作後状態、入力/戻る/確定/折り畳み/キーボードを確認。基準版780×360のODOはパネル324pxに対し内容507px、overflow visibleを再現。変更後は画面内でスクロールし、確定/戻るに到達できる。テストfixtureと画像は合成データだけを使用。

追加で実HomeScreen・BrowserRouter・repositoryを使う隔離Chromium検証を360×780と900×800で実施。合成運行で運行終了ODOの戻る・給油Escapeの前後にtrip/events/routesが完全一致し、その他終了→休憩開始→ページ再読込後も同一snapshotを保持、休憩終了後も元運行と履歴を維持。AI要約・履歴・メッセージ導線の存在と画面表示を確認した。

独立エージェントによる差分レビューとテスト再実行でも公開停止事項なし。ただしこの文書単独では正式公開成功を証明しない。公開状況はRelease、対象SHAのCI、公開APK検証結果で照合する。

## 更新方法

1. 運行終了を画面で確認し、安全な停車中に更新する。進行中は更新しない。
2. [公式の最新APK](https://github.com/Koutacode/tracklog-pwa/releases/latest/download/tracklog-assist-debug.apk)をダウンロードして開き、Androidの「更新」を選ぶ。アプリの更新案内・設定の最新版確認も利用できる。
3. アプリ名TrackLog、v0.1.68、既存ログイン・履歴・日報・位置/通知権限を確認する。
4. 問題時にアンインストール、ストレージ消去、再登録をしない。既存の運行記録を保持し、症状を記録する。

復旧は同じpackage/署名で修正し、より大きいversionCodeの新Releaseを公開して上書き更新する。古いAPKへダウングレードしない。正式APKは既存Android Release workflowで生成し、latest・version・code・署名・SHA sidecarを照合する。公開後の検証値・CI/Release URL・Drive保管結果は既存月次作業ログへ追記する。
