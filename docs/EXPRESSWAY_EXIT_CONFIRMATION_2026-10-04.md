# ETC退出確認の改善（ドラフト・未公開）

2026-10-04 JST。基準main/public v0.1.68: `838931b741be154d6213fe8e43265dc8e855b195`。
利用者承認は修正・テスト・ドラフトPRまで。マージ、タグ、APK公開、実機更新は行わない。

## 変更前後

| 場面 | 変更前 | 今回の追加 |
| --- | --- | --- |
| 止まらず短く減速してETCを通過 | 既定34km/h未満が24秒続かないと終了照会なし | 有効な速度列で34km/h以上から未満へ減速し、減速度が既存の-0.28m/s²以下なら地点を保存。ETC付近の回答で確認通知へ |
| 通過直後に加速 | 低速継続条件が途切れる | 保存した短時間減速地点を保持し、その地点を照会。加速だけでは取り消さない |
| 約10秒間隔の測定の間にETCを通過 | 低速サンプルを捉えられないと候補にならない | 高速区間中、60秒以上かつ200m以上移動して道路を確認。5分以内の異なる2地点（200m以上離れる）で道路外なら確認通知へ |
| SA停止 | 既存の低速継続＋道路判定で確認 | 既存経路を維持。追加照会待ちより旧経路を優先し、SA確認を待たせない |
| 「まだ高速中」の後に実際に退出 | 既定42km/h以上20秒の回復まで再確認抑制 | 旧回復条件を維持しつつ、回答から60秒以上・前回検知地点から500m以上離れた場所では追加経路で再確認可能 |

自動で高速区間を終了しない。既存の「終了／継続」通知・ダイアログ・終了記録経路を使う。走行中の操作や不自然な減速は不要。通知への回答は安全に操作できる時点でよい。

## 負荷・保護

- GPS取得要求の約10秒間隔、権限、署名、package、認証、サーバーAPIを変更しない。
- 追加判定は精度50m以内の有効な位置・速度に限定。停止中の定期道路照会はしない。
- 追加の新規照会は通常最大60回/時。短時間減速が繰り返される合成条件でも追加経路全体で最大120回/時。既存照会・通信再試行・IC名解決はこの数に含まない。実バイト量・サーバー実負荷は未測定。
- 同時の未完了照会は既存どおり1件。追加候補は最大1地点を別に保持。旧低速継続照会が追加照会を置換する場合も短時間減速地点を保持する。
- 候補・道路外証拠・継続回答の地点を既存native状態JSONの任意追加フィールドに保存。旧形式の読み込みを維持し、DB migrationはない。
- 運行/区間のrevision、probe ID、最大5分の追加証拠鮮度を確認。古い応答・重複応答を無効化し、重複通知・重複終了を防ぐ。
- 本番DB、実運行記録、本人端末のIndexedDB/localStorage/SharedPreferencesは取得・変更・削除していない。テストは合成データと隔離JVM Android環境のみ。
