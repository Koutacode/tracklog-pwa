# 検証用ファイルの自動片付け

2026-09-23作成。OneDrive配下に置いたUI検証用ファイルが読み取り専用属性／アクセス権のエラーや削除の審査に阻まれて残り、利用者が手動で消す負担が発生したため、今後の作業用フォルダーを管理する仕組みを追加した。これはPC上の開発作業用であり、Androidアプリの更新は必要ない。

## 保存先と運用

一時ファイルは `%LOCALAPPDATA%\TrackLog\temporary-work` の新規フォルダーへ保存する。フォルダー名は用途とGUIDの組合せ。公開APK、採用した候補APK、端末退避tar、恒久的な記録は従来の `output` や `docs` に保存する。

通常の片付けはCodexが担当する。利用者が毎回コマンドを実行する運用にしない。以後の作業手順は `AGENTS.md` に反映した。

## 作業の実行から片付けまで

検証用PowerShellスクリプトは次の引数を受け取る。

```powershell
param([Parameter(Mandatory = $true)][string]$TemporaryWorkspacePath)

# ログ、UI fixture、ビルド複製などはこの配下へ作成する。
# 残す成果物は作業終了前に既定の保存先へコピーして検証する。
```

次の形式で実行すると、成功・例外のいずれでも終了処理でフォルダーを削除する。

```powershell
npm run temp:run -- -Name ui-qa -ScriptPath C:\path\to\verify-ui.ps1
```

スクリプトは失敗時に `throw` でエラーを伝え、起動した子プロセスやファイルハンドルは終了前に閉じる。ネイティブコマンドの失敗は `$LASTEXITCODE` を確認してエラーにする。

追加の値は `-ScriptArguments` の位置引数として渡せる。名前付きパラメーターを文字列から再解釈する機能は持たせない。

対話的な検証では作成と削除を分ける。

```powershell
npm run temp:create -- -Name ui-qa
npm run temp:list
npm run temp:remove -- -WorkspaceId <作成時に返ったID>
```

作成結果の `Path` を保存先に使う。終了時に自分が起動したサーバー等を止め、必要な記録を残した後、返されたIDを指定して片付ける。中断後は一覧で自分の残存作業を確認する。PC停止やプロセス強制終了では終了処理を実行できない場合がある。

一覧の `Active` はこの仕組みの実行ロックの状態であり、`Create` 後の対話作業や外部サーバーの使用状況までは判定しない。`Active=false` だけで削除を決めず、その作業の終了を確認する。

## 削除の制約

- 削除先は固定の一時領域直下だけ。任意パス、ワイルドカード、一括削除は指定できない。
- 作成時の管理情報とID・作成元プロジェクトを照合する。実行中のロックがある場合は削除しない。
- 祖先と削除対象内のjunction、symlinkなどのreparse pointを拒否し、別の場所をたどって消さない。
- 既存の管理外フォルダー、リポジトリのソース、配布APK、端末バックアップ、端末データを自動で取り込まない。
- 正規のPowerShellファイル操作を使う。ツール側の審査が再度拒否した場合は迂回せず、対象と失敗状態を報告する。

OneDriveの同期領域を避け、保存先と所有範囲を明確にするが、将来のすべての削除が承認される保証ではない。以前拒否されたファイルの削除を別経路で試すための仕組みとして使わない。

## 検証

`npm run test:temp` で管理フォルダーの作成・削除・実行終了時の片付けと、安全上の拒否条件を検証する。GitHub CIではPowerShell 7とWindows PowerShell 5.1で同じ検証を実施する。

2026-09-23のローカル検証では、Windows PowerShell 5.1.26100.9444とPowerShell 7.6.6でそれぞれ13ケース成功、失敗0、テスト用フォルダー残存0を確認した。正常な作成・一覧・削除、読み取り専用ファイル、管理情報の改変、パス逸脱、使用中ロック、junction先の保護、作業の例外・終了コード、片付け失敗時の報告、複数引数を検証した。

独立レビューで見つかった外部コマンド終了コードの見落としと、試験で見つかったPowerShell 5.1の複数引数の扱いを修正して再検証した。公開APKと端末退避tarのSHA256は変更前と一致した。既存の削除拒否対象を新しい仕組みで操作していない。
